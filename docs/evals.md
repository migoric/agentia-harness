# 评测：断言、旋钮、多轮

## 断言只能来自 trace 与最终文本

不用 LLM 当裁判 —— 裁判自己不确定，RSI 就会把随机波动当进步。

```md
---

name: triage-basic
split: train # 或 holdout：留出集只在候选选定后验一次
expect_contains: 优先级
expect_tools: [repo_triage] # 子序列匹配，允许中间夹别的调用
expect_max_tokens: 20000 # 挡住「靠堆循环混过去」
---

判断 issue #12 的优先级
```

## 断言全集

全部是规则式，没有一条依赖模型判断：

| 字段                                          | 判据                                                       |
| --------------------------------------------- | ---------------------------------------------------------- |
| `split`                                       | `train`（缺省）参与归因与提案；`holdout` 只在最后验一次    |
| `expect_contains` / `expect_not_contains`     | 最终文本必须 / 不得包含某些子串                            |
| `expect_matches`                              | 最终文本匹配正则（加载期就编译，坏正则退出码 2）           |
| `expect_tools`                                | 工具名按序出现（子序列，允许中间夹别的调用）               |
| `expect_tool_counts: [grep:2]`                | 工具调用**精确**次数 —— 与上面的子序列语义刻意分开         |
| `expect_tool_args: [grep:foo.c]`              | 该工具入参里必须含某子串（frontmatter 行内数组不能含逗号） |
| `expect_skills`                               | 必须命中的技能                                             |
| `expect_ok`                                   | 是否正常收尾（缺省 true）                                  |
| `expect_max_tokens` / `expect_max_iterations` | token / 轮数上限                                           |
| `memory_keys: [notes, profile]`               | 这条用例走记忆（水合这些键）。缺席 = 裸 agent，不接记忆    |

## 四个旋钮

各自的语义都是刻意的：

| 旋钮                | 缺省   | 为什么                                                                                      |
| ------------------- | ------ | ------------------------------------------------------------------------------------------- |
| `--timeout <ms>`    | 不超时 | 超时**按失败记**并写进失败原因。超时由 harness 自己 race 兑现，不依赖下游配合               |
| `--concurrency <n>` | `1`    | 并发会让「这轮花了多少」与「哪条贵」互相污染，而成本归因是 RSI 的输入。结果顺序永远按用例名 |
| `--retries <n>`     | `0`    | **只对「跑崩了」重试**（`stopReason=error`）。断言失败重试等于用采样次数掩盖问题            |
| `--repeat <n>`      | `1`    | **同一条用例重复采样**，用来把噪声和真实变化分开。与 `retries` 正交，见下一节               |

报告里带 `skillHits`（每个资产被多少条用例走过），这是提案「该改哪个文件」的数据来源。

## 重复采样：为什么单次跑分不是测量

模型采样温度不是 0，所以**同一条用例、同一份资产，两次跑分本来就可能一个过一个挂**。
在 `--repeat 1`（缺省）下，报告里的 `passRate` 是**一次观测**，而回归门却拿它当判据：
88% → 92% 可能只是两次抽样之差，`pass_rate_dropped` 会据此否决一个本身没问题的提案，
反向的假进步还会被记进账本、成为下一轮的先验。

`--repeat n` 把每条用例跑 n 次，于是有两样东西第一次变得可算：

| 产出 | 口径 | 读法 |
| --- | --- | --- |
| `CaseResult.samples` / `passedSamples` | 这条用例采了几次、过了几次 | 报告里显示成 `PASS(2/3)`。**过半即通过**（`passedSamples * 2 >= samples`） |
| `EvalReport.passRate` | 样本级微平均 `Σ passed / Σ samples` | `--repeat 1` 时与旧的「用例级比值」逐位相同 |
| `EvalReport.passRateLow/High` | Wilson 95% 区间 | 小样本、极端比例下都不越界（正态近似的 ±1.96σ 在这里会算出负数） |

两个刻意的取舍：

**过半数就算这条用例通过。** 要求「次次通过」等于把长尾当退步：温度不为 0 时任何
正常改动都会偶尔掉一次，RSI 会因此学到「什么都别改」。判「有没有退一步」的活交给
区间与 z 检验，不给这个布尔加戏。

**门只在显著时才否决。** `pass_rate_dropped` 之前先做两比例单侧 z 检验（α=0.05）：

- 两边采样数相同且 ≥ 2、用例集相同 → 算 z；`z < -1.645` 才按退步否决；
- 否则退回点估计，**行为与没有这个特性时完全一致**（老报告、`--repeat 1`、采样数不一致）。

不达显著时结论是 `pass_rate_dropped_not_significant`：`ok: true`，但 code 单独标出来。
这不是「没看出问题」，而是「看出了一个下降，当前采样量不足以支持结论」—— 下一步该做的是
加大 `--repeat`，不是再改一版提示词。理由里带次数、采样量与 z 值，就是为了让人能自己复核。

> 一个实测到的边界：`--repeat` 只减小**测量**噪声，不减**环境**噪声。同一条用例的 3 次
> 采样共用同一个提示词、同一个模型，严格说并不独立，所以 Wilson 区间偏窄一点点 ——
> 方向是「更容易判出显著性」，也就是更保守地保护判据。这个方向是选的，不是疏忽。

**成本是 n 倍，别默认开。** `--repeat 3` 意味着基线、候选、留出集、回归检查**每一处**
评测都跑 3 遍，`--max-cost` 也更容易提前触发。它该用在「要拿结论的时刻」（验证一个准备
采纳的提案、复现一次可疑的退步），而不是日常顺手跑一次评测。缺省 `1` 是刻意的。

## 记忆要显式声明

`memory_keys` 不写就是不接记忆。这不是省略而是刻意的缺省：线上若接了记忆，同一条用例两次跑结果本就该不同，评测会把这读成「抖动」，回归门永远在抖；反过来，线上有记忆而评测没有，通过率再高也证明不了线上。

每次尝试用的是**全新空 store**（重试若带着上次的残留，就不是「同样条件再来一次」）。预置记忆内容暂不支持 —— 那个格式要等业务框架的记忆形态定下来再定。

## 留出集不是附加题

提案和验收用同一批评测，闭环必然过拟合：模型照着验收用例改，门当然放行。给一部分用例写 `split: holdout` 后，归因与候选排序只看 train；留出集在唯一候选选定后跑一次，用默认硬门，退步就整轮不采纳（不回头试第二候选 —— 那会让留出集变成第二个调参集）。

全是 holdout 或 `split` 拼错会在加载期退出码 2。

## 多轮用例

一次追问、一次纠正之后模型还能不能做对，单轮用例测不出来。用一行 `<!-- turn -->` 把后续轮次写进同一个正文（首段仍是 `task`）：

```md
---

name: fix-path
expect_contains: bar.c
expect_tool_counts: [read_file:2]
---

先看下 foo.c 里的函数
<!-- turn -->
不对，我要的是 bar.c
```

跑法与单轮完全同一条路（`app.run` + agentia 的会话存储），差别只在每轮投一句、历史由上游拼接。三条口径必须记牢：

- **断言看哪一轮**：文本类（`contains` / `matches`）只判**最后一轮**；工具、token、
  迭代数看**所有轮次的累计**。`turns` 记计划轮数，`failedTurn` 指出第几轮崩的。
- **中间轮失败即中止**：会话只在 run 成功收尾时追加历史，失败轮不留痕迹。继续跑会让
  后面几轮在一段真实会话里不会出现的上下文上作答 —— 那种结果既不能当失败证据，
  也不能当通过。
- **多轮用例不能 harvest**：一条 traceId 对不上多段任务原文，压成一句就是另一个场景，
  所以在 `--from-report` 反查时直接拒绝。
- **`expect_ok: false` 的语义**：判的是**整段会话**。任何一轮非正常收尾都算「如你所愿」，
  且 `failedTurn` 仍会指出是哪一轮 —— 反向断言不等于放弃诊断。
- **超时与重试按整段算**：`--timeout` 是整段会话的预算（轮数越多每轮分摊越少），
  `--retries` 重放**整段**（新会话），只计成功那次尝试的成本；超时/抛异常时报告仍会
  保留已跑完那几轮的 token，并指出卡在第几轮。

空轮次（分隔符后面忘了写内容）在加载期就以退出码 2 拒绝，不会等到跑到一半才炸。

## 把一次真实运行变成回归用例

`harness harvest <traceId>` 把一条 trace 回流成 `evals/harvest-*.md`。先跑 `harness eval --keep-traces --save report.json` 把 trace 留下。

trace 里**没有任务原文**（root span 只记模型与配置），所以必须给 `--task`，或用 `--from-report` 从那份报告按 traceId 反查（报告里带每条用例的 `task`）；前缀匹配到多条时拒绝，写文件不接受歧义。

生成的断言只有 `expect_ok: true`，注释里列出观察到的工具、技能与收尾状态 —— trace 记的是**实际行为**，不是**正确行为**；把当时调过的工具固化成断言，等于把错误一起固化。结果类断言（`expect_contains` / `expect_matches`）要人补。已有的用例文件不会被覆盖。
