# RSI：闭环、回归门、跨轮

RSI = 采集 → 归因 → 提案 → 验证 → 采纳/回滚。唯一写源文件的地方是最后一步。

```
采集 collectFailures  ←  一份 EvalReport
  ↓
归因 attribute         ←  规则式聚类（可单测、可解释、零成本）
  ↓
提案 propose           ←  唯一用 LLM 的一步：怎么改
  ↓
验证 verify            ←  在内存 AssetSet 副本上改，跑 eval，零副作用
  ↓
采纳 accept / 回滚 revert  ←  唯一写源文件的地方（原子写 + journal）
```

## 回归门：字典序 + 硬否决

不是一个加权总分：

| 条件                             | 结论                                 |
| -------------------------------- | ------------------------------------ |
| 两份报告的用例集不同             | 否决（`case_set_changed`，分母变了） |
| 有「基线过、候选挂」的用例       | 否决（能指名是哪条）                 |
| 通过率下降（同名用例内）         | 否决                                 |
| 通过率没升、成本/ token 涨超 10% | 否决                                 |
| 通过率提升                       | 放行（token 涨多少都放行，只记录）   |

为什么不用加权总分：权重随手一调就能让任何结论成立。字典序的每一条都能用一句人话解释，而 RSI 最贵的成本不是算力，是**人重新信任一套自己看不懂的提示词**。

## 「可比」需要证据，不是默认成立

报告会带上 `model` + `models`（实际用过哪些）/ `harnessVersion` / `finishedAt` / `caseFingerprint`；`harness report` 把它们打出来，不一致时告警。

`model` 是生效值（单值），`models` 是**实际尝试过的集合** —— 配了 fallback 链之后两者在降级发生时就分叉，而「能不能比」要读的是后者：基线降级过、候选没降级，通过率差异会被读成 agent 的进退步。

用例集变了默认拒绝（加一条候选没做的用例会让分母变大、通过率下降，那不是「整体退步」，是基线过期）；确实只想比同名用例时加 `--allow-case-set-change`，此时 token 与成本也只在同一批用例上算，结论里写明「只比对 N 条」。

判「更贵」优先用**美元成本**（`trace.totalUsage.costEstimate` 逐条累加），两边都有读数时不再看 token —— token 只对同一模型可比，而「换模型」是合法提案。任一条用例没有成本读数（模型不在价格表内）就退回 token，并把 `costBasis` 一并记录：结论用的是哪个指标，必须可复核。「不知道花了多少」与「花了 0」是两件事，混成一个数会让成本门静默失效。

## 一轮最多采纳一个

同时采纳三个，评测从 70% 涨到 85%，没人知道是哪个起的作用 —— 单变量是让「采纳记录」变成可信知识的唯一做法。

## 三层可观测（借鉴 AHE / Superagentic 的思路）

| 层   | 产物                                                                                                                        | 回答的问题                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 经验 | `harness evidence --from-report <报告.json>` → `.workspace/evidence/<id>/` 的 `overview.md` / `detail/*.md` / `raw/*.jsonl` | 失败到底是什么样？（原始 trace 不整坨塞提示词） |
| 决策 | 提案与 journal 里的 `manifest`：依据、假设、预测、风险                                                                      | 当时**为什么**相信这个改动？                    |
| 对账 | `harness rsi ledger [--json]`                                                                                               | 预测兑现了吗？（被拒的尝试也进账本）            |

清单在提案时、验证之前写好，不许事后倒推；账本把 journal 的预测和 cycle 的实际门结果拼在一起，标 `realized` / `not_realized` / `unverified`。证据目录以 id 命名且**不覆盖**：它是事后审计物，覆盖等于销毁历史。

## 手写提案与自动提案走同一条门

自动闭环与手写提案走同一条路：`rsi accept --from` 也先按 train 验证，再跑留出集，最后才落盘。CLI 没有任何开关能跳过留出集；库层的 `acceptProposal` 也会拒绝「工程配了 holdout、却没有留出集验证结果」的调用（手伪造内部结果结构体属于越过信任边界）。

**提案来源可以换，门不能换。** 缺省由 `LlmProposer` 生成；也可以手写一份 L1 提案 JSON，用 `rsi propose --from` 登记（存到 `.workspace/rsi/proposals/<id>.json`），再把那个路径交给 `rsi accept --from` 采纳。手写提案**照样跑完整两遍评测与回归门**（没有跳门的 `--yes` 开关），并且 `patch.before` 必须与当前资产正文逐字相等 —— 来源是人还是模型，验证路径是同一条。

## 跨轮自进化

一轮只采纳一条改动（单变量原则），所以「自进化」得靠多轮串起来，而不是靠一轮改三个：

| 能力     | 命令                           | 关键约束                                                                                   |
| -------- | ------------------------------ | ------------------------------------------------------------------------------------------ |
| 连续多轮 | `harness rsi --rounds 5`       | `--max-cost` 是**整次运行**上限（跨轮共享）；没有可采纳改动就停；`--dry-run` 与它互斥      |
| 跨轮记忆 | 自动                           | 提案前读账本，把 `not_realized` / `reverted` 的方向列进提示词；`historyConsulted` 落盘可查 |
| 回归监测 | `harness rsi regress`          | 拿最近一次采纳的 `candidate` 当基准跑全集；有回归退出码 1                                  |
| 自动回滚 | `harness rsi regress --revert` | 仍过 `revertLast` 的指纹校验（采纳后被人手改过就拒绝）                                      |

记忆是软约束：账本里被否掉的方向会以「已经试过、但没成立的方向」出现在提案提示词里，并明确要求换一种改法。**为什么必须这样**：不读历史时提案器每轮都在重置，会把上一轮刚被门否掉的改法原样再提一遍，白烧一遍评测钱 —— 而它看起来完全正常。

`historyConsulted` 是三态的：缺席 = 这轮根本没走到提案（基线就超预算 / 没有失败样本），`0` = 提了案但没有可参考的历史，`N` = 带了 N 条历史。

`rsi regress` 默认**只报告不动手**。自动回滚会改资产，而改资产是这套系统里唯一不该无声发生的事，所以要把 `--revert` 显式写出来。

**手工采纳同样可监测**：`rsi accept --from` 也会落一份轮次记录（与自动 RSI 同一个 `writeCycle`），否则 `regress` 只能报「找不到基准」—— 手写提案的改动就永远在监测之外。

**坏记录会让下一轮当场失败**：`.workspace/rsi/cycles/*.json` 或 `journal.jsonl` 里出现半截 JSON 时，读账本与读基准都直接报错（退出码 2），**不会跳过**。静默跳过会让「预测兑现率」与「有没有回归」两个数字同时失去意义；修好记录之前不要继续跑。
